WaveGain 1.5.4

ReplayGain adjusts the audio samples. Applying gain and undoing it are lossy.

WaveGain v1.5.4
 Usage: wavegain [options] input.wav [...] (also .w64)

 OPTIONS
  -h, --help       Prints this help information.
  -a, --album      Use ReplayGain Audiophile/Album gain setting, or
  -r, --radio      Use ReplayGain Radio/Single Track gain setting(DEFAULT).
  -q, --adc        Apply Album based DC Offset correction.
                   DEFAULT is Track based DC Offset correction.
  -p, --no_offset  Do NOT apply DC Offset correction.
  -c, --calculate  Calculates and prints gain settings, and DC Offsets BUT
                   DOES NOT APPLY THEM - This is the DEFAULT.
  -x, --scale      Writes scale values to stdout in the format: n.nnnnnn
                   In Album mode it only writes the Album Scale value, and
                   in Title mode it only writes the Title Scale values.
                   ONLY works in Calculation mode.
  -y, --apply      Calculates and APPLIES gain settings, and applies
                   DC Offset correction.
  -w, --write      Writes a 'gain' chunk into the Wave Header.
                   Stores the scalefactor applied to the wave data as a
                   double floating point number. Only written when gain
                   is applied. Presence will result in file being skipped
                   if reprocessed.
                   (Unless '--force' or '--undo-gain' are specified.)
      --force      Forces the reprocessing of a file that contains a 'gain'
                   chunk and will result in the new scalefactor overwriting
                   the existing value.
      --undo-gain  Reads the scalefactor in the 'gain' chunk and uses the
                   value to reverse the previously applied gain. This will NOT
                   recreate a bit identical version of the original file, but
                   it will be rescaled to the original level.
      --rf64       Write RF64 when WAV output exceeds 4 GiB. Without it,
                   such output keeps 0xFFFFFFFF sizes (an "oversized" WAV,
                   read to the end by most tools), as earlier versions did.
 NEW OUTPUT AND MEASUREMENT OPTIONS
      --output FILE       Write a single explicit input to a new file (-y or undo).
      --output-dir DIR    Write to a new directory, preserving subdirectories
                          with recursive input. Must be outside input directories.
                          Existing outputs are never replaced; input is retained.
                          Cannot combine output paths with --stdout or --fast.
      --lufs              Select BS.1770 integrated loudness instead of ReplayGain.
                          Default target: -23 LUFS; minimum duration: 400 ms.
      --target-lufs X     Set target (-70..-5 LUFS); implies --lufs.
                          Album gain uses a common gate across all valid tracks.
                          Silence/below-gate material uses manual gain only.
      --true-peak         Measure DC-corrected true peak and limit linear gain
                          to -1 dBTP by default, even with --noclip.
      --true-peak-mode X  precise (default, 16x), fast (4x), or extended.
                          Implies --true-peak; applies to output checks too.
                          extended adds a longer 16x FIR with screened evaluation.
                          It can cost substantially more CPU. All analyze all frames.
                          All are finite estimates, including extended;
                          under-read can exceed the 0.1 dB gain reserve.
                          Separate from --fast; cannot combine with it.
      --peak-ceiling X    Set true-peak ceiling (-60..0 dBTP); implies --true-peak.
                          A 0.1 dB margin plus quantization room is reserved.
                          Quantized output is checked with the selected peak meter.
                          A ceiling too low for the output bit depth is rejected.
                          stdout may contain partial output on a failed check.
                          LUFS/true peak require full analysis. Stdin is calculation
                          only and requires -p and finalized container sizes.
                          Cannot combine with --fast or --undo-gain.
                          Peak limits may prevent reaching the LUFS target.
      --dither-profile X  legacy (default) or rate (requires -d 1..4, integer output).
                          rate uses TPDF and first-order error feedback with a
                          sample-rate-dependent coefficient; -d 1 is unshaped.
                          Light/Medium/Heavy knees: 10/6/3 kHz, respectively.
                          This is a separate family from the legacy F44 filters.
                          Legacy -d 1 uses full high-pass TPDF at every bit depth;
                          legacy -d 2..4 retain their F44 noise shaping.

[Builds with recursive/pattern support]
  -z, --recursive  Search for files recursively, each folder as an album
  -l, --log        Write log file.(Default filename = WGLog.txt)
  -f, --logfile    Specify log filename. (Assumes -l if present.)
  -n, --noclip     Disable gain prevention; PCM output still obeys its sample limits.
  -d, --dither X   Dither output, where X =
               0   for       dither OFF (default).
               1   for       dither without Noise Shaping.
               2   for       dither with Light Noise Shaping.
               3   for       dither with Medium Noise Shaping.
               4   for       dither with Heavy Noise Shaping.
  -t, --limiter    Apply a smooth tanh limiter above half full scale (-6dB).
  -g, --gain X     Apply additional Manual Gain adjustment in decibels, where
             X = any floating point number between -20.0 and +12.0.
                   Clipping Prevention WILL be applied UNLESS '-n' is used.
  -s, --fast       Calculates and prints gain settings - DOES NOT APPLY THEM.
                   NOTE: This method does NOT process all samples, it only
                         processes up to 200 blocks of 16,384 frames (one sample
                         per channel). Results will
                         NOT be as accurate as a full analysis but, with most
                         material, will be within +/- 0.5db. Audio data of
                         8,192,000 bytes or less is analysed in full.
                         DC Offset is neither calculated nor corrected in
                         FAST mode.
  -o, --stdout     Write output file to stdout.
 FORMAT OPTIONS (One option ONLY may be used)
  -b, --bits X     Set output sample format, where X =
             1     for        8 bit unsigned PCM data.
             2     for       16 bit signed PCM data.
             3     for       24 bit signed PCM data.
             4     for       32 bit signed PCM data.
             5     for       32 bit floats.
             6     for       16 bit 'aiff' format.
         NOTE:     By default, the output file will be of the same bitwidth
                   and type as the input file.
[Windows builds only]
  -e, --exec Cmd   Execute a command after wavegain.
                   The following environment variables are available:
                   INPUT_FILE, INPUT_FDIR, INPUT_RDIR, INPUT_NAME,
                   TRACK_GAIN, TRACK_PEAK, TRACK_SCALE, TRACK_NEW_PEAK,
                   ALBUM_GAIN, ALBUM_PEAK, ALBUM_SCALE, ALBUM_NEW_PEAK,
                   DC_OFFSET_L, DC_OFFSET_R
                   %VAR% references to these are expanded after cmd.exe
                   parsing, so file names are never treated as commands.
                   They do not expand inside pipes. '!' is not allowed.
 INPUT FILES
  WaveGain input files may be 8, 16, 24 or 32 bit integer, or floating point
  WAV or Sony Wave64 files with 1 or 2 channels and a sample rate of 192000Hz, 176400Hz, 96000Hz, 88200Hz,
  64000Hz, 48000Hz, 44100Hz, 32000Hz, 24000Hz, 22050Hz, 16000Hz, 12000Hz,
  11025Hz or 8000Hz.
  With --lufs (or --target-lufs), 5.1 and 7.1 WAV/RF64/Wave64 are also
  supported. They require WAVEFORMATEXTENSIBLE masks 0x3f or 0x60f (5.1),
  or 0x63f (7.1). Other/unknown surround layouts are rejected.
  Without LUFS, surround input is warned and refused, except --undo-gain.
  Surround cannot use --limiter or AIFF output. LFE is excluded from LUFS,
  but receives the common gain and is included in sample/true-peak protection.
  No LFE boost, crossover or bass management is applied.
  16 bit integer 'aiff' files are also supported.
  Use '-' for stdin (calculation only). Wave64 input remains Wave64
  when gain or a PCM format change is applied. RF64 input is supported.
  WAV files with 0xFFFFFFFF sizes (written to a pipe, or over 4 GiB) are
  read to the end of the file.
[Builds with recursive/pattern support]
  Quote wildcard patterns so the shell passes them to WaveGain:
      wavegain '*.wav'
  Matching is case sensitive on POSIX and case insensitive on Windows.

 PEAK AND GAIN
  Peak is measured after the selected DC correction. New Peak predicts
  the scaled peak BEFORE limiting, dithering and output quantization.
  Manual gain is added once, then capped unless --noclip is used.
  --limiter does not remove this cap; combine with --noclip to bypass it.

 HIGH SAMPLE RATES
  At 176.4/192 kHz, legacy ReplayGain uses a 127-tap low-pass FIR and 2:1
  downsampling for ANALYSIS ONLY (to 88.2/96 kHz). Output rate is unchanged.
  LUFS and true peak are measured directly at the source sample rate.
  Existing rates retain their original ReplayGain analysis path.
