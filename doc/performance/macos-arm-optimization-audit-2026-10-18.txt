Apple Silicon enablement audit of Windows ARM64 optimization work
Date: 2026-10-18 (Asia/Tokyo)
Source: de0a68a41086c93c7c1a88bb4f842e29868bc1d6
Label: WaveGain 1.5.1 candidate (unreleased; version string remains 1.5.0)

Outcome
-------
The Windows ARM64-tested audio optimizations are already enabled on native
Apple Silicon by the standard O2 build. There is no Windows-only gate that
needs relaxing for the relevant audio kernels. No product source or default
build policy was changed. Windows-specific file handling and diagnostics
are OS implementations, not disabled Mac audio acceleration.

Source/build audit
------------------
* gain_analysis.c:385 selects paired double-vector filters for supported
  Clang/GCC AArch64, independent of the host OS. Apple clang defines both
  __aarch64__ and __arm64__. The preprocessed default has:
    WAVEGAIN_FILTER_PAIR_SUPPORTED=1
    WAVEGAIN_FILTER_SIMD=1
    WAVEGAIN_HAVE_FILTER_PAIR=1
    WAVEGAIN_STEREO_HISTORY=1
    WAVEGAIN_MONO_REUSE=1
  Neither fast-math nor historical HAVE_SSE2 is enabled. Those exclusions
  protect exact arithmetic / backend selection and should remain in place.
* The AArch64 default caches paired stereo histories and fuses the Yule and
  Butterworth stages. Actual O2 assembly contains paired-double fmul.2d,
  fadd.2d and fsub.2d instructions, not merely an enabled preprocessor flag.
* Mono filter reuse is enabled on all supported builds, including macOS.
* Integer PCM specialization (audio.c), integer no-dither/no-limiter gain
  processing (dither.c), mirrored high-rate resampler histories (resample.c)
  and local peak/DC accumulators (wavegain.c) have no Windows-only gate.
  They are already compiled into the Mac binary. DC evaluation guards and
  FP contraction/vectorization restrictions preserve legacy rounding.
* Full stereo-history retention intentionally stays off on x64 because of
  register pressure; earlier x64 experiments regressed. This is an ISA
  distinction, not a Windows/Mac distinction. Do not force it for Intel Mac
  based on the native Apple Silicon results here.
* O3/ThinLTO remains explicitly selectable through RELEASE_OPT/LTO_FLAGS.
  Standard O2 does not disable these source optimizations. Earlier macOS
  O2/O3 validation is recorded in macos-validation-2026-10-18.{txt,json}.

Verification with the normal Mac build
--------------------------------------
make verified-release CC=clang passed. The default path matches scalar
filter sample bits, API histories, histograms, resets, chunk boundaries,
mono/stereo transitions and non-finite guards at all 12 filter rates.
Twelve complete CLI PCM-conversion cases match scalar output bytes.
Loudness kernels match the reference bit-for-bit at 14 rates, including
mono/stereo, exact block energies, gating, irregular chunks, silence,
denormals, edge peaks and the peak-only adapter.
The existing obsolete/unused -s warning from the macOS toolchain remains.
The repository-root binary is the resulting standard O2 release build.

Isolated stereo-history comparison
----------------------------------
Apple M1 Pro, native arm64, Apple clang 21.0.0. Same source and flags:
  -D_FILE_OFFSET_BITS=64 -DHAVE_CONFIG_H -O2 -D_FORTIFY_SOURCE=2
Reference additionally defines WAVEGAIN_STEREO_HISTORY=0, retaining the
former paired two-pass filters. Candidate uses untouched defaults.
Other optimizations are identical between the two binaries.

Existing tools/benchmark_native.py; synthetic 180-second stereo WAVs;
one warm-up and five alternating timed runs, medians, warm OS caches.
Process launch and I/O are included; copying and hashes are outside timing.
Complete apply-output file SHA-256 matches for every format. No new test
harness or product feature was added.

These are incremental effects of stereo-history retention, not total
v1.5.0-to-candidate speedups. At 192 kHz, resampling contributes much of the
cost; the filter improvement is diluted. Synthetic warm-cache results do
not establish real-program, cold-storage or Intel Mac throughput. This
optimization concerns ReplayGain filters, not the separate LUFS engine.

Reproduction
------------
Build two separate binaries from the recorded commit with the above flags,
adding -DWAVEGAIN_STEREO_HISTORY=0 only to the reference. Then run:
  python3 tools/benchmark_native.py --reference /path/history-off \
    --candidate /path/default --seconds 180 --runs 5 --output /tmp/result.json
  make verified-release CC=clang
Paired JSON contains exact flags/compiler identity, selected macros,
assembly examples, executable hashes, all timings and output hashes.
