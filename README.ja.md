# WaveGain v1.5.4

[English](README) | 日本語

WaveGainは、モノラル・ステレオ・対応サラウンドの音声ファイルのラウドネスを測定・調整するツールです。ReplayGainとBS.1770の統合ラウドネス（LUFS）に対応し、True Peakによるピーク制限も利用できます。ゲインは音声サンプルに直接適用します。

既定ではゲインを計算・表示するだけです。`-y`で入力ファイルに適用し、`--output`または`--output-dir`を併用すると原本を保持できます。ゲインの適用と取り消しは非可逆処理です。

## 主な機能

- ReplayGainまたは統合LUFSによる、曲単位・アルバム単位の音量調整
- LUFSモードでの、配置を明示した5.1ch・7.1ch音声への対応
- True Peakの測定と出力上限の指定
- 原本を保持する別ファイル出力と、ディレクトリの再帰処理
- WAV、RF64、Sony Wave64への対応と、16-bit AIFF/AIFCの限定的なサポート
- 8〜32-bit整数PCMおよび浮動小数点音声、8〜192 kHzの14種類のサンプルレートへの対応
- 従来のディザと、サンプルレートに応じて係数を変えるディザの選択

## 対応形式と大容量ファイル

WAVとWave64のモノラル・ステレオ、およびLUFSモードでの対応5.1ch・7.1ch配置の整数PCMと浮動小数点音声に対応します。
サラウンドの配置や制約は「サラウンド対応」を参照してください。
対応サンプルレートは次の14種類です。

```text
8000, 11025, 12000, 16000, 22050, 24000, 32000,
44100, 48000, 64000, 88200, 96000, 176400, 192000 Hz
```

圧縮コーデックには対応していません。16-bit整数のAIFF/AIFC入力にも対応します。`-b`で出力サンプル形式を選択でき、`-b 6`は16-bit AIFF出力です。AIFFには32-bitのコンテナーサイズ制限が残ります。

### WAV・RF64

- POSIXビルドでは64-bitのファイルオフセットを使用し、4 GiBを超えるファイルを処理できます。
- 4 GiBを超える通常のWAV出力は、RIFF/dataサイズを`0xFFFFFFFF`に設定し、警告を表示します。
- `--rf64`ではJUNKチャンクを予約し、必要になった場合だけ64-bitサイズを持つds64チャンクへ変換します。小さい出力は通常のRIFF/WAVのままです。
- `--rf64`にはシーク可能な出力先が必要です。`--stdout`では無視します。RF64入力にも対応し、書き換え時は同じ出力サイズ規則に従います。
- シーク可能な入力では、サイズが未確定値の場合やdataがEOFを超える場合、ファイル末尾まで読み込みます。標準入力では厳密にサイズを検査します。

### Sony Wave64

- GUIDで入力を判別します。AIFF出力を明示しない限り、ゲインの適用やPCM形式の変更後もWave64を維持します。
- コンテナー・チャンクのサイズとサンプル数は64-bitです。単一の音声データチャンクより前に、形式チャンクが必要です。
- 音声の前後にある未知のチャンクは、メモリ使用量を制限してコピーします。`fact`と`gain`は音声より前に書き直し、古くなった`levl`ピーク情報は削除します。
- シーク可能な入力で未確定・切り詰められたサイズを検出した場合は、警告して読み込みます。標準入力の検査は厳密です。
- WAVからWave64への出力変換オプションはありません。最初の`.w64`ファイルは外部の変換ツールで作成してください。

### ゲイン記録と標準入力

任意の`gain`チャンクには、`--undo-gain`用に適用済みの倍率を記録します。これはWaveGain独自の拡張で、プレーヤー向けのラウドネスタグではありません。Wave64では独自GUID（`e217d848-96be-4ac0-b56a-8b46289c71e0`）と、リトルエンディアンのIEEE倍精度浮動小数点数を使用します。

macOSでは、上流実装の仕様によりWAVの`gain`倍率をビッグエンディアンで保存するため、他のプラットフォームとの間でWAVの取り消し用メタデータに互換性がありません。

計算モードで`-`を指定すると標準入力を読み込みます。LUFS・True Peakの標準入力測定には、さらに`-p`と確定済みのコンテナーサイズが必要です。ゲインの適用にはファイル入力が必要です。

## 使い方

ビルド後、リポジトリのルートで実行してください。PATHの通った場所へインストールした場合は、`./wavegain`を`wavegain`に読み替えます。

入力を変更せずにReplayGainを計算します。

```sh
./wavegain input.wav
```

原本を保持し、ReplayGainを適用した別ファイルを作成します。

```sh
./wavegain -y --output normalized.wav input.wav
```

目標を-23 LUFS、True Peakの上限を-1 dBTPに指定して調整します。

```sh
./wavegain -y --target-lufs -23 --peak-ceiling -1 --output out.wav in.wav
```

曲間の相対音量を保ち、アルバム全体に共通のゲインを適用します。

```sh
./wavegain -y -a --output-dir normalized track1.wav track2.wav
```

ディレクトリを再帰的に処理し、各フォルダーを1枚のアルバムとして扱います。

```sh
./wavegain -y -a -z --output-dir ../normalized ./album
```

24-bit整数PCMへ変換し、サンプルレート対応の中程度のノイズシェーピングを使用します。

```sh
./wavegain -y -b 3 -d 3 --dither-profile rate --output out.wav in.wav
```

適用したゲインを記録し、後で取り消します。この例は入力ファイルを書き換えます。取り消しても元の音声とビット単位では一致しません。

```sh
./wavegain -y -w recording.w64
./wavegain --undo-gain recording.w64
```

別ファイル出力では、既存の出力先を上書きしません。`--output`は明示的に指定した入力ファイル1個を対象とし、`--output-dir`は複数ファイルに対応します。再帰処理では相対ディレクトリ構造を保持します。出力ディレクトリは入力ディレクトリの外側に指定してください。

POSIXでは入力の通常のアクセス権を引き継ぎます。所有者・グループや特殊なモードビットはコピーしません。上書き禁止renameとハードリンクがどちらも使えない場合（一部のexFAT・SMB実装など）は、出力先を排他的に新規作成してコピーします。この経路ではコピー中のファイルが見える場合があり、一時ファイルと出力の両方の空き容量が必要です。失敗時は、不完全な出力と完成済みの一時ファイルを保持して通知します。

## ラウドネス・ピーク・ディザ

### ReplayGainとLUFS

どちらも、録音ごとの「聴感上の音量」をそろえるために使います。
ReplayGainは音量正規化の仕組みの名前、LUFS（Loudness Units relative to Full Scale）は
ラウドネスの測定単位です。WaveGainでは、従来のReplayGain方式と、
BS.1770に従って統合ラウドネスをLUFSで測る方式を選択できます。

| WaveGainでの比較 | ReplayGain（既定） | LUFSモード（`--lufs`） |
| --- | --- | --- |
| 周波数の重み付け | 従来の等ラウドネス近似（Yule／Butterworthフィルター） | BS.1770のK-weighting |
| 時間方向の集計 | 50 ms単位のエネルギーの95パーセンタイル値を使い、大きい音の区間を重視 | 重なり合う400 ms単位のエネルギーを統合し、無音や十分に小さい区間をゲートで除外 |
| 目標 | 従来のReplayGain校正基準。`-g`で手動のdB調整を加算 | 既定は−23 LUFS。`--target-lufs`で指定可能 |
| チャンネル | モノラル／ステレオ | モノラル／ステレオと、対応5.1ch／7.1ch配置 |

LUFSの測定値は音量の水準、ゲインのdB値は音量の変更量です。
例えば、測定値が−18 LUFSで目標が−23 LUFSなら、手動調整やピーク保護を考慮する前の
必要ゲインは−5 dBです。ReplayGainは独自の基準に対する変更量を直接求めます。
周波数の重み付け、集計方法、目標が異なるため、同じ音源でも結果は変わります。
従来のReplayGainの結果を統合LUFSへ一律に換算する固定の差分はありません。

従来のWaveGainの結果を維持したい場合は既定のReplayGainを使います。
LUFSで目標を指定したい場合、BS.1770メーターと比較する場合、サラウンドを処理する場合は
LUFSモードを使います。どちらも曲単位・アルバム単位で選択でき、一定のゲインを適用します。
正規化自体が曲中の音量変化を圧縮するわけではありません。True Peakは別のピーク測定で、
`--lufs`だけでは`--true-peak`は有効になりません。
ゲインを適用する場合（`-y`）、どちらのモードもPCMを直接変更し、
プレーヤー用ReplayGainタグは書きません。

他のツールには、BS.1770で測定してReplayGainタグを作るものもあります
（ReplayGain 2.0など）。上の比較表のReplayGainは、WaveGainの従来方式を指します。

参考：[ReplayGainの計算方式](https://replaygain.hydrogenaudio.org/calculating_rg.html)、
[ITU-R BS.1770-5](https://www.itu.int/dms_pubrec/itu-r/rec/bs/R-REC-BS.1770-5-202311-I%21%21PDF-E.pdf)、
[EBU R 128](https://tech.ebu.ch/docs/r/r128.pdf)。

既定の方式はReplayGainです。最大サンプル値だけで正規化するのではなく、重み付けフィルターと音声のエネルギーから知覚上の音量を推定します。トラックモードは各ファイルを個別に調整し、アルバムモードは共通のゲインを適用して曲間の相対音量を保ちます。

`--lufs`を指定すると、BS.1770の統合ラウドネスを使い、既定の目標は-23 LUFSになります。`--target-lufs`は目標値を変更すると同時にLUFSモードを選択します。アルバムのLUFSは各曲のLUFSを平均するのではなく、各曲のブロックエネルギーに共通のゲートを適用して求めます。

LUFSの測定には400 ms以上の音声が必要です。無音や絶対ゲートを下回る音声には、指定した手動ゲインだけを適用します。正確なブロックエネルギー履歴を保持するため、履歴のメモリ使用量は音源の長さに応じて増加します。

### True PeakとDCオフセット

`--true-peak-mode precise`（既定）は385タップ・16倍補間、`--true-peak-mode fast`は全対応レートで49タップ・4倍補間を使用します。どちらもTrue Peakを有効にし、全フレームを解析して出力の再測定にも同じモードを使います。ReplayGain・LUFSの計算精度は変えません。一部だけを解析する既存の`--fast`とは別の機能で、併用はできません。

高速モードの使用例は`wavegain -y --true-peak-mode fast input.wav`です。高速モードではピークの過小評価が0.1 dBの余裕を超える場合があります。高域のピーク精度を重視する用途では`precise`を選んでください。どちらも有限長FIRによる推定であり、あらゆる連続時間波形や後段のサンプルレート変換に対する上限保証ではありません。公式の適合信号による検証は継続課題です。

`--true-peak`はTrue Peak測定を有効にし、既定で-1 dBTPを上限にします。`--peak-ceiling`は上限値を変更し、True Peak測定も有効にします。指定したTrue Peak上限は、`-n`（`--noclip`）でも有効です。

量子化後の出力も再測定し、上限を超えた場合は出力ファイルの公開・置換を行いません。ピーク制限によって目標LUFSに届かない場合があります。`--stdout`では送信済みの音声を取り消せないため、最終検査の失敗は非ゼロの終了コードで通知します。

DCオフセット補正は既定でトラック単位です。`-q`でアルバム単位に変更し、`-p`で無効にします。`-p`の場合、LUFSとTrue Peakは最初の解析読み込みで同時に測定します。DC補正後の値を測定する場合は、追加の読み込みが必要です。

`--true-peak-mode extended`は、より長い16倍補間FIRと候補を絞る評価を追加します。
過渡的なピークの評価を補う一方、CPU負荷が増える場合があります。
このモードも有限長フィルターによる推定です。`precise`・`fast`とともにv1.5.2で追加済みです。

### ハイレゾ入力とディザ

176.4/192 kHz入力のReplayGain解析では、ローパスFIRと2:1の間引きを使用します。LUFSとTrue Peakは元のサンプルレートで測定します。出力のサンプルレートとフレーム数は維持します。

ディザの既定プロファイルは`legacy`です。`--dither-profile rate`には`-d 1..4`と整数PCM出力が必要で、TPDFノイズと、サンプルレートに応じた一次誤差帰還を使用します。`-d 1`はノイズシェーピングなしです。新しいオプションを選択しない場合、従来の対応レートのReplayGainと従来のディザは元の処理経路を使用します。

### 測定エンジン

MITライセンスのlibebur128を同梱し、R128Netを参考にしたCの最適化、ステレオのブロックエネルギー計算のSIMD化、ピーク測定専用の処理経路を追加しています。libebur128の別途インストールや.NETランタイムは不要です。

実装、ライセンス、精度の条件は[実装概要](doc/design/loudness-implementation.md)を参照してください。

## サラウンド対応

5.1ch・7.1chのWAV／RF64／Wave64は、`--lufs` または `--target-lufs` を
指定すると処理できます。未指定時は警告し、そのファイルを処理せず終了状態1を返します。
測定が不要な `--undo-gain` は例外です。

```sh
./wavegain -y --lufs --true-peak --output surround-out.wav surround.wav
```

WAVEFORMATEXTENSIBLEのチャンネルマスクは、5.1chの `0x3f`（back）と
`0x60f`（side）、7.1chの `0x63f`（side＋back）に対応します。
出力でも配置と順序を保持します。配置不明・未対応の入力、サラウンドAIFF／raw入力、
AIFF出力、`--limiter` との併用は対象外です。

LFEはLUFS測定から除外しますが、決定したゲインはLFEを含む全chへ同じ値を適用します。
サンプルピーク保護と任意のtrue-peak保護も全chが対象です。LFEのピークによっては
目標LUFSに達しません。LFEだけの音源は手動ゲインのみを使います。
LFEへの追加の+10 dB、クロスオーバー、ベースマネジメントは行いません。
5.1chのサラウンドと7.1chの側方は測定時のエネルギー重み1.41、
7.1chの後方は1.00です。アルバムDC補正はスピーカー位置ごとに集計します。

## ビルドとインストール

Cコンパイラーとmakeを用意し、リポジトリのルートで実行します。

```sh
make
```

既定のリリースビルドは、64-bit環境を含むコンパイラーのネイティブアーキテクチャを使用します。PCMの格納には固定幅の32-bit型を使用します。x86で32-bitビルドを明示する場合は`make CFLAGS=-m32`を使用します。Debianの`gcc-multilib`など、追加のヘッダーとライブラリが必要になる場合があります。

既定のインストール先は`/usr/local/bin`です。`prefix`で変更できます。

```sh
sudo make install
# /usr/binへインストールする場合
sudo make install prefix=/usr
```

インストールターゲットはGNU形式の`install`オプションを使用します。macOSでは、ビルドした実行ファイルをPATHの通ったディレクトリへコピーする方法も利用できます。

Windowsでは、MSYS2のMINGW64シェルでMinGW-w64 GCCと同じMakefileを使用するか、Visual Studio 2022以降で`mswindows/WaveGain.sln`を開きます。新しいMSVCプロジェクトはC17、Win32/x64、精密な浮動小数点設定に対応します。対応するVS Developer Command Promptから`python tools/check_msvc.py`で共有テストを実行できます。旧`.vcproj`・`.icproj`は過去の設定です。MinGWのリリースビルドは`_FORTIFY_SOURCE`用のlibsspを静的リンクし、システムDLLだけに依存します。他のコンパイラーやCPUでの検証は継続します。

`debian/`のパッケージ設定は過去のもので、保守されていません。古いdebuild手順には依存せず、ソースからビルドしてください。

## テストと開発

本体のCソース・ヘッダーと生成ヘルプは`src/`、テストと音声サンプルは`test/`、開発ツールは`tools/`、同梱ライブラリーは`vendor/`にまとめています。設計資料は`doc/`、詳細な調査記録はgit管理対象外の`local-research/`に保存します。ビルドは従来どおりリポジトリーのルートで実行し、実行ファイルもルートに生成されます。

| コマンド | 内容 |
| --- | --- |
| `make debug` | 追加のコンパイラー警告を有効にしてビルド |
| `make check` | 回帰テスト一式を実行（Python 3が必要） |
| `make check-sanitize` | ASan/UBSanで再ビルドし、テストを実行 |
| `make check-interop` | FFmpegとの比較（ffmpeg/ffprobeが必要） |
| `make verified-release` | ReplayGain・ラウドネスの一致検証付きリリースビルド |
| `make check-loudness` | ラウドネス測定処理をネイティブの参照実装と比較 |

PCM・浮動小数点変換、ゲインと取り消し、メタデータ、不正ファイル、5 GiBのWave64を含むスパース大容量ファイル、出力パス、ラウドネス、True Peak上限、リサンプリング、ディザの信号特性を検証します。未完了の検証項目は[TODO](TODO)に記録しています。

`verified-release`は、同じコンパイラー・フラグで作成したスカラー版とReplayGainのフィルター状態・変換出力を比較し、高レートFIRの出力と履歴も参照畳み込みと照合します。不一致なら実行ファイルを削除します。`VERIFY_SIMD=auto`が既定で、どちらのバックエンドも許可します。`VERIFY_SIMD=1`はステレオSIMD版、`VERIFY_SIMD=0`はスカラー版を要求します。

GNU互換コンパイラーのx86_64ビルドは、ReplayGainの履歴をレジスターに保持するSSE2アセンブラと、高レートFIRの8出力並列処理を使用します。AVX2は実行時に判定し、非対応CPUではSSE2を使用します。ビルド時に`-DWAVEGAIN_X86_ASM=0`を定義するとC経路、`-DWAVEGAIN_X86_AVX2=0`でSSE2のみのFIR経路を検証できます。FMAを全体で有効にしたビルドのFIRは、従来の丸めを保つためスカラー経路を使用します。

CLIヘルプとマニュアルの正本は[doc/help.json](doc/help.json)です。変更後は`make docs`で生成し、`make check-docs`で英語READMEのヘルプ、`src/help_generated.h`、manページ、HTMLマニュアルの同期を検査します。日本語READMEは手動翻訳のため、オプションや挙動の変更時にはこちらも更新してください。

Clangでは`make verified-release CC=clang RELEASE_OPT=-O3 LTO_FLAGS=-flto=thin`で最適化ビルドを検証できます。GCCのLTOは`LTO_FLAGS=-flto`を指定します。通常ビルドは従来どおり`-O2`です。`verified-release`はラウドネス処理と参照実装の一致も検証します。非有限値の検査と演算の正確性を保つため、fast-mathは使用しないでください。

Windowsでは`python tools/check_windows.py --cc aarch64-w64-mingw32-clang --optimized`でネイティブの回帰試験を実行できます。`--optimized`を省略すると`-O2`、コンパイラーを`x86_64-w64-mingw32-clang`に変えるとx64向けになります。ARM64上でのx64試験はWindowsのエミュレーションを利用します。

テスト一覧と個別実行の方法は[test/README.txt](test/README.txt)にまとめています。`python test/run_suite.py --list`で一覧、`--only NAME`で指定グループを実行できます。Windowsのビルド用スクリプトに`--ubsan`を追加すると、未定義動作と浮動小数点から整数への変換オーバーフローも検査します。

旧版との出力比較には`test/pcm_equivalence.py`、速度と出力一致の同時測定には`tools/benchmark_native.py`を使用できます。どちらも`--reference`と`--candidate`で実行ファイルを指定し、ベンチマークでは`--output timings.json`も指定します。Windowsでは`.exe`を含むパスを指定してください。測定にはウォームキャッシュを使用するため、実素材や低速ストレージでの性能を保証するものではありません。詳細な調査記録・計測JSON・レビュー履歴は、Git管理外の`local-research/`で管理します。このフォルダはcloneやリリースには含まれません。

## 動作の変更点

### バージョン1.5.4

- 明示的なチャンネル配置を持つ5.1ch・7.1chのLUFS処理、全chのピーク保護、ディザ、形式変換、取り消しに対応します。
- サラウンド入力に`--lufs`または`--target-lufs`がない場合は警告して処理しません。測定が不要な`--undo-gain`は例外です。従来のReplayGainはモノラル・ステレオが対象です。

### バージョン1.5.3

- 入力の重複検査に、実行全体で共有するパス・ファイルIDのハッシュ索引を使用します。大規模な再帰処理での検査負荷を減らし、元のファイルと書き換え後の別名の重複も防止します。
- 同梱LUFS・True Peakの履歴と作業バッファが、任意レートで丸めた400 ms区間を保持できるようにしました。CLIの対応サンプルレートは変更していません。
- 高レートのFFmpeg比較にはフェード付き信号を使い、急な終端のピークは独立した波形再構成テストで引き続き検証します。
- Windowsの`--exec`はシステムの`cmd.exe /d /v:on`を使用し、WaveGainの変数は構文解析後に展開します。ファイル名の特殊文字をコマンドとして解釈させません。パイプ内の変数展開と`!`を含むコマンドには対応せず、変数を使う引数内の`^`はエスケープとして働きます。空白を含む実行ファイルのパスは1組の引用符で囲みます。

### バージョン1.5.2

- 整数PCMのDC解析で正確なブロック和と補償加算を使います。従来の0.1 dBや16-bit DCしきい値未満を含む、ゼロでないゲイン・DC補正も適用するため、書き換えるファイルが増える場合があります。
- アルバムDCは実在するチャンネルごとに時間で重み付けし、同じ長さの音源は保存サンプルレートにかかわらず同じ重みになります。
- LUFSのK-weightingを直列の2次フィルターに変更し、高レートでの安定性を改善しました。11025 Hzでも400 ms区間と100 ms間隔を正確に扱います。
- ノイズシェーピングなしの従来ディザは、24/32-bitを含む全ビット深度で十分な振幅のハイパスTPDFを使います。ディザは既定では無効で、シェーピング付きの振幅は維持します。
- `--true-peak-mode precise|fast|extended`を追加しました。`precise`は既定の16倍補間、`fast`は全レートで4倍補間、`extended`は候補を絞る評価と長い16倍補間で過渡ピークの測定を補います。選択したモードを出力検証にも使います。いずれも有限長フィルターによる推定です。
- ファイルごとに従来ディザの全履歴をリセットし、端数ブロックでもステレオのシェーピング位相をそろえます。形式をまたぐ過渡ノイズや終端の誤差を防ぎます。
- 符号付き32-bit PCMの最小値−2147483648を、1 LSB切り上げずに保持します。
- 既定のTrue Peak測定は全レートで385タップ・16倍補間し、高域での過小評価を減らします。ピーク制限時のゲインと出力が変わる場合があります。
- 高レートReplayGainのFIRでFMAを明示的に無効化し、FMA対応ビルドでもSSE2/AVX2の高速経路を使用します。従来FMAを使っていたFIRの丸めが変わる場合があります。
- MSVC向けの注釈・精度設定を整備し、Win32/x64対応のプロジェクトとネイティブ回帰テストを追加しました。旧`.vcproj`・`.icproj`は過去の設定です。

### バージョン1.5.1

- Wave64のUndo倍率、不完全なPCMフレーム、拡張WAVの矛盾した精度・拡張長を、原本の書き換え前に拒否します。
- 同じ入力やファイルIDが同じ別名を各処理バッチの開始前に拒否し、ゲインの二重適用を防ぎます。先に完了した別バッチの処理は保持されます。
- Windowsのコマンド構築にシェルの長さ上限を適用し、環境変数用ファイル名の固定長コピーを廃止しました。アルバム・コマンド用DC表示も大きなfloat音声の値を安全に扱います。
- ARM64のステレオReplayGain解析で履歴を保持し、2段のフィルターを連続処理します。ピーク・DC集計もローカル変数で行い、高速化しました。フィルター演算、DCの加算順序、出力音声を維持します。
- モノラルのReplayGain解析で同一の左右フィルター計算を共用し、高速化しました。ステレオ入力へ切り替わった後は独立した処理に戻し、履歴・丸め・出力音声を維持します。
- Windowsの再帰探索では、途中で見つかったジャンクションなどのディレクトリリンクをたどりません。明示指定したリンク先は入力に使えます。出力先は実際の場所で判定し、別名でも入力内にある場所や、場所を確認できない場合は拒否します。
- 整数PCM入力と高サンプルレート用FIRの履歴参照を高速化しました。復号後のサンプル値とフィルターの加算順序を維持します。
- ディザ・リミッターなしの整数ゲイン適用を専用化しました。従来の量子化、DC補正、飽和境界を維持します。
- Windows x64で、gainメタデータ内の極小のbinary64値が正しく書き込まれるようにしました。
- Windowsのディレクトリエラー表示で元のエラー番号を保持し、メッセージ中の`%`やシステムメッセージ取得失敗を安全に処理します。

### バージョン1.5.0

- 別ファイル出力を追加し、原本を保持しながら既存の出力先への上書きを防止します。
- POSIXの別ファイル出力は入力の通常のアクセス権を引き継ぎます。上書き禁止renameやハードリンクに非対応のファイルシステムでは、排他的な新規作成とコピーを使用します。
- ReplayGainの代わりにLUFSを選択でき、アルバムでは共通のゲーティングを使用します。
- True Peak上限は`--noclip`でも有効で、量子化後も検査します。目標LUFSに届かない場合があります。
- 176.4/192 kHz入力と、選択式のサンプルレート対応ディザを追加しました。

### 過去の変更と互換性

- WAVヘッダーは検証済みのチャンク境界で更新します。`fmt `などの文字列を含む不透明なメタデータを保持し、奇数長RIFFチャンクとデータのパディングを扱います。
- 16-bit AIFF/AIFCからWAVへの変換に対応します。未対応の8-bit AIFF/AIFC、不正なヘッダーやgainチャンクは、入力を置換する前に拒否します。
- 空の音声や一括処理の一部失敗を含め、解析・変換失敗は非ゼロで終了します。処理済みとして意図的にスキップしたファイルは成功扱いです。出力確定時の書き込み・コピーを検査し、失敗時は原本を保持します。Windowsでも原本を先に削除せず、一時ファイルは排他的に作成します。
- 極端な浮動小数点値や取り消し時の増幅は、整数化の前に飽和させ、量子化器やノイズシェーピング履歴のオーバーフローを防ぎます。
- クリッピング防止と表示される`Peak`には、選択したDC補正後のピークを使用します。
- どちらかのチャンネルのDCオフセットがフルスケールの1/32768を超えた場合に補正します。以前のしきい値は2/32768でした。
- `-t`（`--limiter`）では、ほかのゲイン変更やDC補正が不要でも全ファイルを書き換えます。
- 88.2 kHzでは、以前の不安定な係数を置き換えたためゲイン値が変化します。従来のSSE2フィルター（`HAVE_SSE2`）を使用するMSVCビルドも、最後のYule係数を無視していた問題の修正により、全レートで変化します。
- ReplayGainフィルターではFMAを無効にしています。AArch64や`-march=x86-64-v3`以降のx86_64など、以前はFMAで計算していたビルドでは丸めが変わり、0.01 dBのヒストグラム境界に近いゲインが1段階動く場合があります（例：48 kHzで-0.44 dBから-0.45 dB）。FMAを使用できないビルドは従来と同じ結果です。同一ビルドのスカラー版とSIMD版はビット単位で一致しますが、RMS集計やlog10まで含めた、全コンパイラー・全アーキテクチャ間の一致を保証するものではありません。
